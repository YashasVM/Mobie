## Main findings

1. Latest Gallery already pins **`com.google.ai.edge.litertlm:litertlm-android:0.18.0`**. Upgrading Mobie from 0.16.1 establishes runtime parity; it cannot establish an advantage over this Gallery snapshot by itself. [G/libs.versions.toml:22-23](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/gradle/libs.versions.toml#L22-L23) [G/libs.versions.toml:75](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/gradle/libs.versions.toml#L75)
2. Gallery does not select the fastest backend by measured device performance. It uses the user's accelerator setting, then the first accelerator listed for the model, then a GPU fallback. Its current Gemma 3n allowlist starts with CPU; Gemma 3, Gemma 4, Qwen, and DeepSeek entries generally start with GPU. [G/Model.kt:234-251](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/app/src/main/java/com/google/ai/edge/gallery/data/Model.kt#L234-L251) [G/BackendSpec.kt:64-70](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/app/src/main/java/com/google/ai/edge/gallery/data/BackendSpec.kt#L64-L70) [G/LlmChatModelHelper.kt:130-136](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/llmchat/LlmChatModelHelper.kt#L130-L136) [G/1_0_20.json:119-205](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/model_allowlists/1_0_20.json#L119-L205)

## 1. Exact Gallery engine and conversation configuration

### Backend selection

`Model.currentAccelerator` parses the stored accelerator label and otherwise returns `backendSpec.defaultAccelerator`. That default is the first entry in the model's accelerator list. The helper maps CPU to `Backend.CPU()`, GPU to `Backend.GPU()`, and both NPU and TPU labels to `Backend.NPU(nativeLibraryDir = context.applicationInfo.nativeLibraryDir)`. A missing text accelerator becomes GPU. There is no S24 Ultra autotuning or CPU/GPU race in this selection path. [G/Model.kt:228-251](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/app/src/main/java/com/google/ai/edge/gallery/data/Model.kt#L228-L251) [G/BackendSpec.kt:64-70](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/app/src/main/java/com/google/ai/edge/gallery/data/BackendSpec.kt#L64-L70) [G/LlmChatModelHelper.kt:118-136](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/app/src/main/java/com/google/ai/edge/gallery/ui/llmchat/LlmChatModelHelper.kt#L118-L136)

The allowlist parser preserves accelerator order, substitutes the TPU label on Pixel devices, and removes GPU specifically on Pixel 10. These Pixel exceptions do not supply an S24-specific policy. [G/ModelAllowlist.kt:130-154](https://github.com/google-ai-edge/gallery/blob/4928788ef07cdf2194fc435a0f446cf3b997bd5d/Android/src/app/src/main/java/com/google/ai/edge/gallery/data/ModelAllowlist.kt#L130-L154)

`Backend.GPU()` is an abstract runtime choice. LiteRT-LM checks the artifact for an Artisan text decoder and can internally change GPU to `GPU_ARTISAN`; Gallery itself does not choose OpenCL versus Vulkan or select a shader implementation. [L/engine_settings.cc:163-211](https://github.com/google-ai-edge/LiteRT-LM/blob/b2f686e2ed4718fb84ec398a61dd59ca0f0aff27/runtime/engine/engine_settings.cc#L163-L211) [L/llm_executor_settings_utils.cc:228-233](https://github.com/google-ai-edge/LiteRT-LM/blob/b2f686e2ed4718fb84ec398a61dd59ca0f0aff27/runtime/executor/llm_executor_settings_utils.cc#L228-L233)

This order prioritizes plausible gains, stock-SDK feasibility, and consumer behavior. It does not rank measured S24 results. Every item **needs on-device measurement**. A result against Gallery's stock default is distinct from a result against Gallery configured with the same backend/MTP/context.

## Suggested future measurement protocol

No measurements were performed for this report. Before claiming an advantage:

1. Record Gallery commit/app version, Mobie commit, SDK version, model repository revision, exact filename, SHA-256, size, weight quantization, chosen backend, context capacity, consumed context, sampler/seed, MTP, thinking budget, and enabled modalities. Use the same `.litertlm` bytes in both apps.
2. Establish both Gallery's stock default baseline and a matched tuned baseline. Test first-turn cold load, first-turn warm cache, repeated turns on an existing conversation, and a 5..10-minute sustained workload. Alternate app order and repeat runs so warming, file cache, and thermal drift do not favor one app.
3. Use a real `Engine` for settings sweeps. The SDK benchmark wrapper ignores CPU thread count. Keep benchmark mode identical where native statistics are needed; also time actual streaming in the normal app mode. Do not assume active benchmark GPU waiting equals interactive behavior.
4. Report native decode tok/s and prefill tok/s separately from app-observed TTFT, first visible answer, load time, and total completion time. For app decode, use actual generated tokenizer/native counts and the same first-token convention. Do not count UTF-16 characters, words, chunks, or Compose updates as tokens. Label Gallery benchmark TTFT as the native estimate.
5. Match prompt content, retained history, output budget, thinking mode, and sampler. Account for reasoning tokens and MTP chunks. A shorter response or truncated history changes workload and cannot establish a kernel throughput gain on its own.
6. Record physical Galaxy S24 Ultra, Android/One UI version, peak process RAM/native memory where available, first-token latency, tok/s, memory failures, cancellation/reset results, thermal status and sustained throttling, battery/power state, and output-quality regressions. Root access and forced clocks are not prerequisites for a consumer default profile.
7. Only promote a profile after the exact artifact loads and completes inference on physical ARM64. The new ModelInfo API is a useful preflight, not load-test evidence. Keep unknown/unsupported configurations blocked rather than silently claiming compatibility.
