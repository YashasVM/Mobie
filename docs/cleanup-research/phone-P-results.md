## Findings and limits

The 12 measured greedy outputs across both modes and their idle reruns share the AUTO reference SHA-256 `268745ad45fc2ee2230c4a083eb57f2c5635e84ed3b3066973bcfa26db10b7df`. This is output identity for one short prompt, not broad quality validation. FP32 is not run (phone unavailable) under the deadline reprioritization.

The Gallery-equivalent configuration in Mobie's harness uses the generic Gallery fallback GPU-first order through Mobie's AUTO selection, no CPU-thread instrumentation override, AUTO precision, fixed artifact context 4096, temperature 1.0 / topK 64 / topP 0.95 / seed 0, thinking off, empty history, and a normalized 64-token output cap. GPU was selected for all repetitions, so native-default CPU fallback threading was not exercised. This exact Qwen3 artifact is absent from Gallery's researched allowlist; its fixed 4096 context takes precedence over the generic fallback 1024. Gallery itself does not set a per-send output cap. The 64-token cap is an explicit normalization for this deadline-limited comparison, and full uncapped Gallery-default reproduction is not run (phone unavailable). Mobie's persistent app-private cache, native benchmark counters, and explicit thinking configuration remain in use; these do not reproduce all Gallery app behavior.

Gallery-equivalent idle rerun median decode 26.02166 tok/s, prefill 179.20950 tok/s, TTFT 1138 ms. These rates cannot establish an identical-workload kernel advantage or superiority over installed Gallery. No Gallery data was accessed or altered.
